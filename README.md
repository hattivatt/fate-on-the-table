# Fate on the Table

Модуль Foundry VTT, который выносит персонажа из чарника на стол (канвас сцены) в виде набора объектов `Drawing` + `Tile`, позволяя разместить его перетаскиванием мыши и автоматически синхронизируя с изменениями актёра. Включает менеджер Fate Points игроков и мастера, менеджер ситуативных аспектов, операцию «Новая сцена» и систему JSON-раскладок виджета.

Система: `fate-core-official`. Foundry: v14 (минимум `14.354`).

## Возможности

### Вынос персонажа на стол

- В меню «⋮» окна чарника (`fcoCharacter`) — пункты **«Вынести на стол»** и **«Убрать со стола»**.
- Размещение в режиме «в руке»: превью следует за мышью, левый клик — подтверждение, ПКМ или Esc — отмена; опциональная привязка к сетке.
- Виджет — группа документов на сцене: портрет, имя, аспекты, блок жетонов FP, таблица компетенций, фон-подложка и прозрачный «хватательный» бокс.
- Автосинхронизация с актёром (тексты, портрет, число жетонов FP, навыки) с дебаунсом; несколько виджетов одного актёра на разных сценах синхронизируются одновременно.
- Перетаскивание любого элемента виджета двигает всю группу; якорь сохраняется.
- Удаление виджета — со сцены исчезают все его рисунки и тайлы, запись очищается.

### JSON-раскладки виджета

Виджет персонажа строится из декларативной JSON-раскладки (формат `fate-on-the-table.layout`, версия 1): виртуальный canvas с origin/sizePolicy, элементы `drawing`/`tile`/`tileRow`, resolver'ы данных, относительное позиционирование (`position.anchorTo` — legacy-совместимая опция), рамки, растущие под контент (`sizing.growTo`), фон и drag-box. JSON не содержит кода — только разрешённые resolver'ы и настройки модуля (`@setting.*`).

- **Встроенные раскладки**: `Default` (текущий вид виджета, доработан в layout-editor: портрет и блок FP смещены, ниже FP-рамки — треки стресса: названия слева, а каждый чекбокс — отдельный drawing-рамка с «X» в зачёркнутых, как в legacy-макросах; боксы стресса подняты над «хватательной» рамкой и **кликабельны** — одинарный клик владельца персонажа заполняет/очищает бокс и синхронизирует `box_values` трека; границы боксов — тонкие, `stroke.width: 1`; последствий `Default` **не содержит**), `Minimal` (имя, портрет, короткие аспекты, стресс и последствия) и `Full` (FP/refresh, аспекты, навыки, стресс-треки, последствия, трюки). В `Minimal` и `Full` label стресса — сверху, а его чекбоксы — отдельной строкой ниже. **Последствия — только текст**: заголовок `consequencesHeader` и строки цены `consequenceCostRows` (занятый слот показывает имя последствия, свободный — его цену с подчёркиваниями), которые редактируются **двойным кликом**; интерактивных consequence-чекбоксов нет. Эти boxRow-элементы заданы абсолютными `rect`/`repeat`; `position.anchorTo` остаётся поддержанной legacy-опцией. Если данные отсутствуют, секции Full/Minimal не создают пустых документов.
- **Короткие аспекты**: resolver `@shortAspects` (mode `value`) выводит первые два непустых аспекта в порядке `system.aspects` (обычно High concept и Trouble) без заголовков и сортировки; пустой actor даёт пустую строку. Встроенная раскладка `Minimal` использует его (элемент `el_3i03bm`) вместо полного блока `@aspects`.
- **Выбор по роли**: настройки **«Раскладка игрока»** (актёры с игроком-владельцем) и **«Раскладка NPC»** (без владельца-игрока; fallback на проверку ownership по не-GM пользователям). «Шаблон раскладки по умолчанию» остаётся фолбэком, если выбранная роль-раскладка недоступна.
- **Идентичность раскладки**: каждый размещённый виджет хранит `layoutId`/`layoutVersion` в своём реестре; смена настроек не перекладывает уже размещённые виджеты. Для старых записей без identity при первом успешном синке автоматически дописывается выбранная роль-раскладка.
- **Смена раскладки** уже размещённого виджета: меню чарника «⋮» → **«Изменить раскладку»** (GM).
- **Менеджер раскладок** (GM): открывается кнопкой **«Раскладки…»** в настройках модуля или инструментом сцены с иконкой таблицы. Внутри — единый список **всех** раскладок: каждую можно **экспортировать** (скачивается JSON-файл); встроенные (`Default`, `Minimal`, `Full`) отмечены «built-in» и доступны только для экспорта; пользовательские можно **переименовывать** и **удалять**. Внизу — **«Импортировать»** (файл или вставка JSON из standalone `layout-editor`): валидация с указанием поля и ошибки; если id импортируемой раскладки уже занят, модуль предлагает ввести новый id вместо отказа. Пользовательские раскладки хранятся в world-настройке `customLayouts` и не могут перезаписать встроенные.
- **Публичный API**: `registerLayout`, `getLayout`, `getLayoutIds`, `validateLayout`, `getLayoutJson` из `scripts/layoutRegistry.js` — другие модули могут регистрировать свои раскладки в памяти.
- **Контракт формата идентичен standalone `layout-editor`**: `scripts/layoutSchema.js` повторяет валидацию и нормализацию редактора (обязательные поля, лимиты, дефолты нормализации, сохранение неизвестных полей), поэтому экспорт любого из двух проектов открывается в другом без ручной конвертации; это покрыто Node-кросс-проверкой и тестами `npm test`.
- Визуальный редактор раскладок — отдельное standalone-приложение `../layout-editor`; модуль содержит только загрузчик, валидатор и импорт/экспорт. При недоступности JSON-ресурсов модуль не падает и использует legacy-JS-раскладку как фолбэк.

### Менеджер Fate Points (GM)

Инструмент сцены **«Менеджер Fate Points»** (иконка звезды в группе «Жетоны», виден мастеру):

- строки игроков: текущие FP / refresh, кнопки «дать» `+` / «забрать» `−` (не ниже нуля), признак наличия виджета на активной сцене;
- секция мастера: текущие FP (`fate-core-official.gmfatepoints`), `+`/`−`, размещение/переразмещение/удаление отдельного ряда жетонов FP мастера;
- **«Синхронизировать всех»** — пересобирает виджеты актёров активной сцены и ряд мастера (новые виджеты не создаются);
- **«Рефреш всех»** — поднимает текущий запас игроков до refresh (завышенный запас не уменьшается);
- **«Новая сцена»** — диалог с выбором количества игроков и переносимым списком ситуативных аспектов; после подтверждения: сохраняются выбранные аспекты в `scene.flags["fate-core-official"].situation_aspects`, FP мастера устанавливаются равным числу игроков, очищается быстротечный стресс (только `Fleeting`: боксы и связанный аспект), выдаётся итоговое уведомление. Отмена не меняет ни одного документа.

Ряд FP мастера — отдельная группа тайлов (без `actorUuid`), реестр `scene.flags["fate-on-the-table"].gmFatePointWidget` `{ widgetId, anchor }`. Перетаскивание ряда сдвигает его целиком и обновляет якорь. При значении FP = 0 реестр сохраняется, тайлы отсутствуют. Если ряд удалён вручную при положительном значении — реестр очищается и ряд не воссоздаётся сам.

### Менеджер ситуативных аспектов (GM)

Инструмент сцены **«Менеджер ситуативных аспектов»** (иконка огня в группе «Жетоны», виден мастеру):

- список ситуативных аспектов сцены из `scene.flags["fate-core-official"].situation_aspects`;
- для каждого аспекта: число свободных invoke с кнопками `+`/`−` (не ниже нуля), переименование и удаление с подтверждением;
- добавление аспекта с названием и начальным числом invoke (по умолчанию 1); при добавлении можно выбрать персонажа из токенов сцены (по имени токена) — принадлежность пишется в название аспекта в скобках: `Аспект (Персонаж)`, тот же формат, что у системной кнопки «add track aspect» в Fate Utilities; по умолчанию — ни к кому;
- изменения применяются **сразу, в реальном времени**: каждое действие (добавить/переименовать/удалить, `+`/`−` invoke) пишет список в scene flag одним `setFlag` и немедленно обновляет размещённый виджет — отдельной кнопки «Сохранить» нет, кнопка «Закрыть» просто закрывает меню;
- **«Разместить на столе» / «Переразместить»** — размещение или переразмещение виджета списка через общий placement-flow (то же действие доступно кнопкой **«Разместить ситуативные аспекты»** в Fate Utilities на вкладке Scene в ряду кнопок ситуативных аспектов);
- **«Убрать со стола»** — удаление виджета с подтверждением (массив аспектов в данных сцены не удаляется).

Виджет — группа из трёх Drawing без `actorUuid`: подложка, текст списка (`name (N)` через пустую строку, по центру) и прозрачный «хватательный» frame. Реестр `scene.flags["fate-on-the-table"].situationAspectsWidget` `{ widgetId, anchor }`. Перетаскивание любого элемента двигает всю группу и обновляет якорь; двойной клик GM по любой части открывает менеджер. Виджет обновляется при изменении системного флага, настроек, загрузке сцены и после «Новой сцены». Наличие флага без размещённого виджета ничего не создаёт; полностью удалённая вручную группа очищает реестр и не воссоздаётся сама.

### Розыгрыш конфликта на столе

Отдельное сценовое поле для ведения конфликта по порядку ходов с зонами, карточками участников и отметками текущего/завершённого хода. **Реализовано (module-side)**: чистая схема состояния (`scripts/conflictBoardSchema.js`), чистая геометрия поля (`scripts/conflictBoardGeometry.js`), сценовая проекция и reconcile (`scripts/ConflictBoardSync.js`), менеджер и порядок ходов (`scripts/ConflictManager.js`), редактор зон (`scripts/ConflictZoneEditor.js`), взаимодействия канваса (`scripts/ConflictInteractions.js`), настройки модуля, i18n-ключи и CSS-классы `.ctt-conflict-*`. Чистые модули покрыты Node-тестами (`npm test`). Интерактивные сценарии — размещение, редактор зон, броски токенов, контекстные меню, окна ApplicationV2, внедрение кнопок в Combat Tracker и Fate Utilities — в Foundry v14 с Advanced Drawing Tools ещё требуют ручной проверки: фича не считается полностью подтверждённой в живом запуске.

- **Источник истины** — стандартный `game.combat`: очерёдность — `combatants` в текущем порядке, текущий ход — `turn`, раунд — `round`, отметка «походил» — флаг `fate-core-official.hasActed` у `Combatant`. Собственный порядок ходов в module flag не создаётся; поле хранит только геометрию, зоны, раскладку карточек и принадлежность токенов.
- **Менеджер и порядок ходов** — инструмент сцены **«Менеджер конфликта»** (ApplicationV2): раунд, список участников с состояниями «ход ещё не начат / ходит сейчас / ход завершён», кнопки **«Следующий ход»**, **«Предыдущий ход»**, **«Завершить ход»**, **«Новый раунд»**, **«Передать ход»** конкретному участнику, добавление участника из токена сцены, удаление и сдвиг вверх/вниз. Текущий участник на поле помечается отдельным Drawing-marker'ом (красный — ещё не походил, серый — походил); «Новый раунд» доступен, только когда все участники походили. Отметка `hasActed` пишется только штатным API Combat и в поле не дублируется; завершение/удаление Combat не очищает поле автоматически.
- **Точки входа размещения** — кнопка **«Разместить на столе»** в стандартном Combat Tracker Foundry и кнопка **«Разместить поле конфликта»** во вкладке конфликтов Fate Utilities (то же действие доступно из «Менеджера конфликта»). Кнопки доступны только GM и только когда активный конфликт привязан к сцене и у участников есть токены на ней; обе точки входа вызывают один общий `placeBoard()`. Повторный вызов на уже размещённом поле не создаёт второе — поле пересинхронизируется и открывается менеджер.
- **Размер и фон** — перед размещением GM выбирает preset `small`/`medium`/`large` (по умолчанию 500/800/1200 единиц сцены, задаются в настройках). Цвет фона (`#ffffff` по умолчанию), текстура (пусто — цветовая заливка) и прозрачность настраиваются в настройках модуля **отдельно** от фона виджета персонажа и ситуативных аспектов. Поле, уже сохранившее собственный `boardSize`, не пересоздаётся при изменении настроек.
- **Карточки участников** — строятся из встроенной раскладки `Minimal` через тот же `layoutRegistry`, что и обычный виджет персонажа; последствия на карточке — только текстовые строки цены, редактируемые двойным кликом (см. «Последствия»).
- **Права** — поле и порядок ходов видны игрокам в режиме только чтения (окно «Менеджера конфликта» у игроков без кнопок управления); размещать поле, менять порядок ходов, редактировать зоны и получать контекстное меню карточек может только GM. Перетаскивание зоны не-GM-пользователем отклоняется.
- **Зоны и принадлежность токенов** — прямоугольные зоны создаются GM drag-ом по центральному полю в режиме **«Редактор зон»** (инструмент сцены: рисование, перемещение, изменение размера за угловые ручки) или через **«Добавить зону»** из контекстного меню поля — это клик-размещение прямоугольника через `PlacementManager` (превью следует за мышью, левый клик фиксирует зону, ПКМ/Esc отменяют; прямоугольник зажимается в границы центрального поля). Размер прямоугольника «Добавить зону» зависит от preset поля: `small` 120×96, `medium` 150×120, `large` 225×180 (единиц сцены; поле меньше preset уменьшает размер до границ поля). Превью и сохранённый прямоугольник всегда совпадают. Принадлежность токена к зоне хранится в scene flag `conflictBoard` (`tokenZones`), а фактические позиции токенов остаются штатными `TokenDocument.x/y` (vision, ownership и стандартный Token HUD не затрагиваются). Бросок токена в зону обновляет принадлежность и снапит токен внутрь зоны; ручное перемещение токена пересчитывает принадлежность.
- **Перезагрузка** — состояние поля (зоны, карточки, принадлежность токенов) сохраняется в `scene.flags["fate-on-the-table"].conflictBoard`, реестр виджетов — в `conflictBoardWidget`; после reload состояние восстанавливается, осиротевшие участники и удалённые зоны безопасно очищаются при reconcile. Завершение/удаление Combat не очищает поле автоматически; полностью удалённая вручную проекция очищает реестр и не воссоздаётся сама.
- **Ограничения первой версии** — зоны только прямоугольные; карточки раскладываются по областям автоматически (стопки «Походил»/«Выбыл» с перекрытием, переполнение не обрезается молча, а отчитывается), но ручное перемещение карточки между областями, «Выбыл»-операции, изменение стиля зоны из контекстного меню, привязка зон к ситуативным аспектам, вложенные/круговые зоны и применение политики переполнения `expand` к геометрии — будущие расширения, не заявленные как готовые. Переименование и удаление зоны доступны уже в первой версии из контекстного меню зоны (удаление — с подтверждением и очисткой принадлежности токенов).

### Настройки

- **раскладка игрока** и **раскладка NPC** (шаблон по умолчанию скрыт и используется только как фолбэк), кнопка **«Раскладки…»** — менеджер раскладок (экспорт/импорт/переименование/удаление), масштаб, привязка к сетке, шрифт, цвет текста;
- изображение FP (общее для виджета игрока и ряда мастера), ширина/высота/шаг жетонов — применяются как runtime-оверрайд к уже размещённым виджетам и ряду мастера без сдвига якоря (рамка жетонов расширяется под фактический ряд);
- текстура фона виджета;
- виджет ситуативных аспектов: ширина, высота, шрифт (пусто — BadScript, если зарегистрирован, иначе Montserrat), размер шрифта, цвет текста, текстура/цвет/прозрачность собственного фона (не наследуется от фона виджета персонажа);
- поле конфликта: размеры presets `small`/`medium`/`large` (единицы сцены, по умолчанию 500/800/1200), цвет/текстура/прозрачность собственного фона (отдельно от других фонов), политика переполнения карточек.

## Установка

В Foundry: **Add-on Modules → Install Module → Manifest URL**:

```
https://github.com/<user>/<repo>/releases/latest/download/module.json
```

Либо скопируйте папку модуля в `Data/modules/fate-on-the-table`.

## Использование

1. Откройте чарник персонажа Fate Core → меню «⋮» → **«Вынести на стол»**, кликните по сцене.
2. Задайте изображение FP в настройках модуля, иначе жетоны не рисуются (числовые значения при этом всё равно корректны).
3. Мастер: инструмент **«Менеджер Fate Points»** — раздача FP, размещение ряда мастера, «Новая сцена»; инструмент **«Менеджер ситуативных аспектов»** — ведение списка аспектов сцены и размещение виджета; инструмент **«Менеджер раскладок»** — импорт/экспорт пользовательских JSON-раскладок и выбор раскладки игрока/NPC.

## Совместимость

- Проверено с включённым модулем Advanced Drawing Tools (тексты получают ADT-флаги выравнивания).
- Старые standalone-тайлы макроса `core.fatePointTrackerPlayer` / `core.gmFatePointTracker` и старые Drawing макроса `core.situationAspectsWidget` не удаляются и не управляются модулем; системный флаг FP мастера (`fate-core-official.gmfatepoints`) и системный флаг аспектов (`fate-core-official.situation_aspects`) используются напрямую.
